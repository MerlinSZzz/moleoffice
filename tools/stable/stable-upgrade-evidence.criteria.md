# Original evidence for a stable upgrade

Old: no stable-upgrade evidence reader or reader-specific criterion existed. The producer kept original receipts, but no reader independently checked a supplied original revision against its artifacts and Git identities.

New: the following checks must all pass before this reader returns evidence. They are added before the implementation because an edited latest receipt or a successful exit alone cannot establish an original complete suite result.

1. Export async verifyUpgradeEvidence({ repository, commit, evidence: { recordId, seq, contentHash } }, { officeRequest }) returning { receipt, original, result, artifacts }. Failures throw. The injected officeRequest takes a GET request object and returns the status/body/cut transport envelope from tools/office-request.mjs. Require status 200, explicit cut false and a JSON object body. Reject masking in the original read and in current provenance; permit it only in explicitly ignored current record data and change metadata. Reject absent or malformed status, redirects, errors, cuts, redacted Git identities and incomplete evidence. Issue only GET requests; take no lock, write no file or record, and start or stop no service. GET bookkeeping is the agreed exception.
2. Require the caller's original sequence 1 and exact content hash. Read /api/records/:id/revisions/1 explicitly. Validate recordId, sequence, create operation, whole_suite_receipt kind, undeleted original content and an agent creating actor with its recorded actor/run identity. Read current only for its id, kind, authored origin and undeleted status. Current data never supplies receipt facts. An edited latest green receipt cannot authorize an original red result.
3. Require a canonical absolute repository root, exact full commit, its actual tree, and membership in refs/heads/main ancestry. A target behind main is allowed. Verify the receipt's repository/commit/tree and actual separate clone root, HEAD/tree and clean working tree, including untracked files, without changing refs or the index. Neither development nor clone root may contain the other. Require the producer's independent clone Git storage: its own regular .git directory and common directory, no alternates, symbolic links or shared object hard links. Disable Git filesystem-monitor commands during every read.
4. Require the producer's original attempt layout: clone/, suite.log, report.json, manifest.json, reads/, door-result.json and door-output.log alongside each other. Reject missing, inaccessible, symbolic-link or displaced evidence. Original method data must identify a completed cloud test phase, requested commit and real exit, finite nonnegative wallSec, positive worker count, and the kept door output's final JSON answer. The result is an artifact consistency check, not an assertion of cryptographic producer identity.
5. Rebuild the receipt with the producer's existing receiptFromArtifacts. Compare every receipt fact, including all canonical base64 SHA-256 digests, paths, counts, failure names, timestamps and Git identities. Ignore only the shared parser's permitted shortForms record metadata. Use the shared wholeSuiteReceiptIsGreen predicate. Require both original method verification and recomputed green evidence; never attribute failures away or substitute local results.
6. Prove behavior through real throwaway Git repositories and made-up original artifacts, read through askTheOffice against a real throwaway office app/database. Exercise edits, red originals, hashes, artifact/method contradictions, clone identities/cleanliness, ancestry, provenance and strict transport failures. The verifier's reads must leave file bytes, refs and office record revisions unchanged. No live database, listening port or cloud suite is involved. Each new test receives control, red mutation and restore proof through run-named-tests using this run's variables.

7. Read version 2 of the receipt as well as version 1. A version 2 receipt keeps each file that was red beside others, and that file's run alone on the same box, in the attempt's alone/ folder: alone/<n>/run.log, and alone/<n>/report.json when the run left one. Rebuild those runs alone from their own files, by the producer's own receiptFromArtifacts, and compare them like every other fact. A run alone's file that is missing, displaced or a symbolic link is refused. The shared wholeSuiteReceiptIsGreen decides: a version 2 receipt is green only when every file red beside others was green alone, so a file red alone, a run alone that gave no result and a file not run alone all keep it not green.

8. Take a version 2 receipt that is not green only when the authorization note pins a judgement of it that stands (wave 13q item 6). verifyUpgradeEvidence then takes `noticeApproval: {id, seq, contentHash}` beside the evidence. It asks the release policy's theJudgementThatStands, which reads the judgement through the same office and judges it by the one rule in src/shared/receipt-judgement.ts. It returns the verified facts with `judgement`, the pin. With no note, or a note that pins none, a receipt that is not green is refused as before. A judgement deleted since the pin is refused with its own sentence. A green receipt is read exactly as before: the release policy, not this reader, refuses a pin beside it.

Masking clarification before implementation: old wording rejected a mask anywhere in either response. New wording permits the mask only in ignored current data/change metadata. An edited latest 64-hex identity is masked by the transport, but supplies no fact about the unchanged original create. Its mask must not alter that original's meaning. Original evidence, relied-on provenance and whole-response status/cut checks remain strict.

Clone method clarification before implementation: old wording required a separate root and exact clean HEAD/tree. New wording requires disjoint roots and independent Git storage, matching the producer's --no-local clone, and explicitly disables filesystem-monitor commands. Matching HEAD alone does not prove that a checkout has its own storage, and Git status can otherwise invoke a configured command that writes files.
