# Destination configuration for offline tools

On Node 22, import readDestinationsOffline from destinations.mjs and pass the database filename. It opens an existing database read-only, reads one runtime_settings row named storage:destinations and closes the connection. It makes no office request and reads no inventory or credential. The returned array contains only names, kinds, target configuration, upload policy, limits in bytes and enabled flags. The shared destination schema validates the stored data; invalid data is refused, not replaced by defaults. New destinations use DEFAULT_UPLOAD_POLICY from the shared storage module. No Vault configuration is synthesized or changed.

Destination names are immutable lower-case identifiers, with letters, digits and hyphens, starting with a letter. The existing backup name is reserved. Folder targets contain path; S3-compatible targets contain endpoint, bucket and prefix; SSH targets contain host, port, user and path. These are configurations only: this implementation runs no transport, enforces no upload quota and produces no receipt. The page reads local sizes through readStorageCategories, and leaves destination holdings and core size unknown until a later receipt implementation can measure them.

Credentials use the same host secrets location declared by the sandbox templates. One environment line is keyed by MOLE_STORAGE_DESTINATION_ followed by the destination name's UTF-8 bytes in uppercase hexadecimal. Its value is base64-encoded JSON, preserving the exact accepted credential field names. The settings database never contains that value. The host writer uses a same-directory exclusive temporary file at mode 0600, flushes it, then renames it. Reads are size bounded and refuse symbolic links, hard links, other ownership and permissions for other users. Retain leaves the line unchanged; replace replaces the whole credential object; remove deletes the line. Unknown fields and credentials in target URLs are refused. Offline credential consumption and all upload transports belong to later work.
