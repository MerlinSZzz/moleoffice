## What the picture does not draw, and why

- **Who starts runs in a sandbox.** The picture draws one arrow for it: the secretaries start runs in the sandbox with the sandbox tool. The message worker starts runs as well: an agent's run for a message, and a worker in a sandbox when a supervisor asks for one (`src/worker/index.ts:3-35`; `src/server/api/worker-runs.ts:1-3, :25-36`; `src/server/lib/worker-runs.ts:26-36`; `tools/sandbox.mjs:140-148`, the worker command). Its box says this as "starts runs", and the picture draws no arrow for it.
- **HTTP, not HTTPS.** The server listens on 127.0.0.1 and the page calls the API port directly (3.1, 3.3). The inventory names no TLS.
- **The live office's setting.** The code lets the message worker start agent runs for messages, checks and the merge tool. In merges-only mode it starts the merge tool, the rounds asked for at the next-round door and the workers a supervisor asks for, and no run for a message (`src/config/settings.mjs:1033-1074`). When the inventory was made, the live office ran in that mode (inventory, the note at the top; 3.4). The picture draws what the code does.
- **The office's key, before an agent is registered.** A session's hook calls the API with the office's key until the agent is registered and its key is set; after that it uses the agent's own key (`tools/session-hook.mjs:650-667`, theHookIdentity). The arrow label "API calls, own key" names the usual case.
- **The checker and the merge tool.** They are drawn in the development-flow picture, as its steps 5 to 9, from "Judged" to "Landed", and not in this one.

## The facts behind the short labels

The picture carries at most two short lines under each title. These are the full statements, each traced in the table above.

- **Web app.** Runs in the user's browser and talks to the server only through its API, over HTTP, with the user's key in the pairing cookie; it hears one server-sent event stream.
- **Secretaries.** Agents whose job is the person, for example Claude Code in a terminal on the user's machine. Each joins the office through session hooks. It calls the API with its own key once the agent is registered and its key is set, and with the office's key before that. It hands large work to supervisors and starts their runs in a sandbox with the sandbox tool, naming itself as the starter.
- **Mole Office server.** One process. Every read and write passes its API layer, which checks each caller's key and role card. Decisions, problems, reports and messages are all records of one kind or another, linked together, and every write is kept whole. Only the user makes regulations; an agent writes a decision only by citing authority or the user's words, and otherwise files a proposal. Changes are pushed to open pages as events, and reminders and counters run in the background.
- **Database file.** One file. The server reads and writes it while it runs. The stable upgrade backs it up and then migrates it (`tools/stable/stable-upgrade-transaction.mjs:1078-1104`). A landing moves only the development main and does not touch it (`tools/merge-tool/the-stable-office.mjs:1-8`). Every change keeps its full history.
- **Sandbox.** A container where agents run: Claude Code, Codex, DeepSeek and others. It cannot reach the database. Each run holds its own temporary key, which ends when the run ends, and talks to the server only through the API.
- **Message worker.** A separate process that the server starts. It starts an agent's run for a message, and a worker in a sandbox when a supervisor asks for one. It starts the check tool and the merge tool, and delivers messages. It calls the API with the office's key.

- **Office flows are one capability, not a column.** The owner's correction of round 8: a technical reader should know the office keeps registered procedures, not read each one. The tile "Office flows" traces to the flow register. The change path the code enforces is drawn in the development-flow picture instead. Neither picture draws that the starter confirms only after the work lands (stage 6 of the flow for the check of a run and its confirmation), so it is said here only.
