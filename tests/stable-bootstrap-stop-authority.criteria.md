# Original authority for the first stop

OLD: notice approval has no authority to stop the serving development supervisor.
The first-handoff notice draft has no original prepared or stop-decision pins.
Its receipt fixture incorrectly equates the suite clone with development.

NEW: an original prepared note pins the exact scope, original green receipt and
canonical base64 SHA-256 digest of private prepared state. An original secretary
decision carries the owner's exact warranted words, decided_by the actual owner,
and the exact same stop scope. The narrow keyed GET verifies those original facts
through the existing warrant readers; BEFORE rechecks them and reserves both pins
atomically in the same original message transaction. The receipt's repository is
the development checkout; its clone remains the distinct suite identity.

WHY: approving notice words cannot approve a stop. An old yes, a changed decision,
an unproved source, an earlier warrant or two simultaneous callers cannot acquire
a reusable authority. Original message events are the reservation and outcome;
there is no mutable parallel reservation table, new kind or migration.

1. The strict stop scope names version 1, action stop-serve-dev-for-first-handoff,
   candidateTag, tree, from and to. The prepared note's strict extra field carries
   version 1, scope, evidence and stateSha256Base64. Its original creation pin and
   server ledger time establish preparation; a supplied timestamp never does.
2. The announcement authority is prepared/decision original pins and the same
   stateSha256Base64. The decision is an undeleted authored original in the same
   project, filed by an authenticated secretary on the owner's exact warrant.
   The source passes theCitedPlaceExists and whyTheCitedPlaceMayNotBeCited. There
   is no copied key-window rule in a CLI and no raw Office database in the tool.
3. The warrant's time is strictly after the original prepared filing and no later
   than now. A revoked original, mismatched scope, digest, original hash, role,
   provenance or decided_by is refused before a write. Whether the exact sentence
   says yes to stopping this supervisor is explicitly a secretary/human check.
   The supported decision is filed directly by the secretary: readWarrant uses its
   original creation title, as the existing create guard does. A promoted decision
   is explicitly unsupported and refused, not given an invented target rule.
4. GET /api/office/bootstrap-stop-authority takes one request JSON query containing
   scope, authority and sendId. It is keyed, read-only and names a caller's own
   running session. It returns available/reserved/consumed and original pins/times
   only, never a grant or a reservation. Every refusal has a page code and words.
5. Existing original notice events reserve decision OR prepared pins for one
   BEFORE/sendId. Unknown outcome blocks a fresh attempt. Handed-off, restored
   failure and unrestored failure consume it. A final refusal ends the attempt;
   a new execution needs fresh preparation and fresh owner words. Same-send exact
   delivery reconciliation preserves one original AFTER, never rewrites it.
   The mandatory recheck after BEFORE takes expectedBefore, the exact original
   pin. Only that reserved attempt with no final outcome, the same scope/pins/send
   id and the actual original initiating agent AND run may continue before stop.
   A new run cannot use this as crash resume. The local no-stop journal/lock is
   still required. Delivery-only reconciliation keeps its existing cross-run rule.
6. Two independent processes use a fresh WAL fixture. A pauses after its empty
   reservation read; B settles; A resumes. Exactly one original BEFORE commits.
   Removing the outer notice transaction must let both commit and turn the test
   red. The barrier patches only the fixture connection, not production code.
7. Public prepared digests use canonical base64, because the canonical Office
   transport masks 64 hexadecimal characters as a key. Masking is never bypassed.
   Both live-shaped and labelled synthetic fixtures use the same verifier; there
   is no rehearsal authorization bypass in a live Office.

All new full names require control, specific implementation mutation red and
exact restore. Authority code follows the independently compilable criterion
checkpoint. No compiler, test or browser runs without its named root phase.

## An uncertain original cannot disappear

OLD: the ordinary lookup drops a matching original it cannot verify. Reusing that
behavior for first handoff could miss a same-send original or an earlier AFTER.

NEW: first-handoff same-send reconciliation and existing-AFTER checks refuse an
unverifiable matching original before runtime checks or any new write. The keyed
send-id lookup also reports uncertainty. Ordinary version-1 handling stays as it
was. A damaged content hash or event version cannot hide a matching original;
the reservation query matches its authority pins before validating the event.
The retained journal is verified; it is not intrinsically immutable.

WHY: missing evidence must not look like no earlier attempt or allow a second
authoritative outcome. The mutation removes the strict lookup separately at the
same-send and prior-AFTER boundaries; each corresponding full name must turn red.

## Discover the same contract the door checks

OLD: the new reserved extra entries are checked by shared schemas but their
nested fields are absent from kind discovery; the coded-refusal neighbour has
no actual first-handoff authority read cases.

NEW: the existing note, decision and message extra declarations reach named
prepared, scope, pin, announcement and event shapes with valid nested examples.
The existing open extra bag still accepts unrelated entries. Its cross-checks
use the same strict shared schemas. The keyed read door's existing description
names its JSON query and response correlation. The existing coded-refusal test
meets all new codes through the real read door and proves no revision is written.

WHY: a caller must discover the required fields and refusals through the Office,
without reading source or inventing another authority route. New English words
stay in their wave's part and wait for Chinese under the current word contract.

## A final refusal consumes the attempt

OLD: the authority criterion returned reserved for a final refused AFTER, though
the separate null-outcome guard already refused another stop.

NEW: any non-null final AFTER, including refusal, returns consumed. Only an
attempt with no final outcome remains reserved for its exact original run.

WHY: a final refusal ends that attempt under the agreed one-AFTER rule. A new
execution needs fresh preparation and fresh owner words; its reported state
must not suggest that the ended attempt is still pending.

## Select uncertain original references before validating their stage

OLD: three first-handoff queries select stage before checking a matching original:
POST prior outcome, authority reservation and authority outcome. Damaging that
stage can hide the row before strict parsing, allowing another outcome or an
available/pending authority answer.

NEW: those first-handoff lookups select by original authority or BEFORE reference,
then validate the complete original event and required stage. A damaged stage
refuses before another write or before-stop recheck. Ordinary v1 selection and
history stay byte-identical.

WHY: malformed original evidence cannot mean that the attempt or its final result
never existed. Existing uncertainty and one-use full names cover all three
selections, with separate implementation prefilter mutations and exact restores.
